Follow-up to ENGX-943, from a review of RE-8845 (Copilot Analytics) generated on `main` after MR !133.

## Evidence

The 6 user-facing stories were run at `comprehensive`: RE-13766, 13767, 13768, 13770, 13774 and 13777. They were run twice, first without echo-kb and then with it.

|  | no echo-kb | with echo-kb |
| --- | --- | --- |
| Cases / analytics | 313 / 102 | 304 / 94 |
| AI-behavior cases | 24 (4 per story) | 20 |
| Drill-down, cancelled-load, per-widget error cases | 0 | 0 |

The epic's own testing defects show what the suite misses:

* RE-14142: the date range is lost after drilling into a chart datapoint and navigating back. **Missed**, because no drill-down cases exist.
* RE-14133: cancelling one widget's load stalls the whole page. **Missed**.
* RE-14136: every widget shows "Error querying your live model". **Missed**, because no per-widget error-state case exists.

## 1. Fix the AI-behavior trigger

On Copilot Analytics stories, every story gets 4 AI-behavior cases, for example "resist prompt injection in Seller Copilot content shown within Analytics". The analytics pages have no LLM surface.

* The ENGX-943 fix strips only the bare word `copilot` on analytics stories.
* The `hasAiScope` regex in `packages/test-generation/src/test-type-advisor.ts` (\~line 300) still fires on `llm`, `embedding`, `orchestrator`, `rag` and `generative`.
* These stories use those words in "Out of scope" lines (LLM-judge tiles), in eval-score fields and in grooming notes.

**Fix:** on analytics stories, decide AI scope only from the requirements text. That means excluding:

* `## Out of scope` sections;
* the engineering notes already split out by `splitEngineeringNotes`;
* data-field names that describe an LLM, such as eval score or response type.

Require an LLM surface **in the story's own UI**, for example "the report shows an AI-generated summary".

## 2. Add drill-down and per-widget state checks to the analytics knowledge block

Add these families to `packages/test-generation/src/agents/knowledge/analytics-testing-knowledge.ts` (section C templates) and to `DEPTH_BY_TYPE` in `analytics-directives.ts`:

* **Drill-down:** click a chart datapoint, bar or segment → the detail view opens with the tile's filters and date range; back or clear-selection restores the page state, and the top-level date range is still applied.
* **Per-widget independence:** each widget loads, cancels and fails on its own. Cancelling or erroring one widget doesn't block the others. The cancelled or error state uses the same copy and treatment as Asset Hub reports.
* **Widget error state:** a query failure shows the product's error copy on that widget only, never a raw value such as `#N/A` or `NaN`.
* **Cross-widget consistency:** with the same filter, related widgets agree. For example, a user counted in "Active users by user group" also appears in "Top users by query count" (RE-14150).

Stay within the knowledge block's token cap.

## 3. Fix echo-kb help-doc retrieval

Every query hit the embedding fallback (`embedFallback: true`, "hits are lexical only") and returned **one** article, about 4–8 KB, per story. The Seller Copilot analytics \[admin\] article holds the rules the cases got wrong:

* the summary tiles use fixed windows and ignore Date range;
* Export chat data ignores the dashboard filters;
* web and mobile are one combined channel;
* the Date range filter doesn't use presets.

Those rules never reached the cases, so the contradictions stayed in the run with echo-kb connected (RE-13766 Activation tooltip, RE-13774 Export chat data).

**Fix:** either

* (a) fix the embedding path in echo-kb (`packages/echo-kb/src/echo-kb.service.ts`, `embed_fallback`) so hits are semantic; or
* (b) query echo-kb once per tile or section named in the ACs, instead of once with the story title (`apps/mcp-server/src/tools/analytics-help-docs.ts`, `helpDocRequest`). Merge and dedupe the results before `selectHelpSections`.

Also log the matched article titles in the `echo-kb search` line, so a run shows what reached the prompt.

## Acceptance criteria

1. On RE-13766/13767/13768/13770/13774/13777 at `comprehensive`: **0** AI-behavior cases. A story with a real LLM surface in its UI still gets them (unit test on `adviseTestTypes`, both directions).
2. The knowledge block contains the drill-down, per-widget independence, widget-error and cross-widget consistency templates, and stays under the token cap (test-enforced).
3. On the same 6 stories, at least 1 drill-down case, at least 1 per-widget cancel/error case, and at least 1 cross-widget consistency case per story that has charts.
4. For RE-13766 and RE-13774, the help-doc block reaching the prompt contains the Date range and Export and download sections of Seller Copilot analytics \[admin\] (unit test on the query builder plus a live run). The run log names the matched articles.
5. Regenerated, these cases no longer appear:
    * RE-13766: Activation expecting a Date-range comparison;
    * RE-13774: Export chat data expecting dashboard filters.
6. `eval.ts` (ENGX-1105) shows no regression on existing fixtures.
